## 3. Verified issues

### AUTH-01 Recovery "dead end" — **partially reproduced, root cause found, fixed (UX)**
- **Actual:** On `/forgot` → security questions, the *Reset password* button is disabled whenever the "Repeat" field is non-empty and differs from "New password" — i.e. on every keystroke until both match. The only explanation was "Passwords don't match." No password rules were shown, so a weak password failed only after submit.
- **Not a dead end:** with matching passwords the button enables (verified in the local app with synthetic input; no reset was submitted).
- **Fix:** rules shown under the field (turn amber when unmet), mismatch message now says the button turns on when both match, Show/Hide toggles, error messages use `role="alert"`.
- **Files:** `src/app/forgot/page.tsx`.

### AUTH-04 (new) One-time code fields mangled pasted codes — **confirmed, fixed**
- **Root cause:** `value.replace(/D/g, "")` strips the letter "D", not non-digits (`/\D/g`). A pasted `123 456` kept its space and verification failed.
- **Files:** `src/app/login/page.tsx` (email confirmation code), `src/app/forgot/page.tsx` (recovery code); helper `digitsOnly` in `src/lib/site.ts`.
- **Regression test:** `src/lib/site.test.ts` → `digitsOnly`.

### AUTH-02 Email field is type=text — **not reproducible**
Live HTML and source both render `type="email" required autoComplete="email"`; server re-validation is done by Supabase.

### AUTH-03 Input carried between forms — **partially reproduced, fixed**
Sign-in and sign-up share one component, so the email *and the typed password* persisted across the mode toggle (intentional for email). The password is now cleared on toggle. `src/app/login/page.tsx`.

### UI-01 No password show/hide — **confirmed, fixed**
New `src/components/password-input.tsx` (aria-label + aria-pressed, 44 px target); used on `/login` and `/forgot`.

### SEC — Security headers — **confirmed, fixed (baseline)**
Live `/login` sent only HSTS (Vercel) and `X-Powered-By: Next.js`. `next.config.ts` now sends `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` and drops `X-Powered-By`. No iframes/camera/mic/location usage exists in `src/`. CSP deliberately deferred.

### Found, not fixed (needs a decision)
- **SEC-02 Security answers sit in plaintext `localStorage`** between sign-up and the first sign-in when email confirmation is pending (`PENDING_QA` in `src/app/login/page.tsx`). Cleared after sign-in. Options: `sessionStorage` (lost if the confirmation link opens a new tab; dashboard already reminds), or drop the pre-confirmation save and ask on first sign-in.
- **SEC-03 Question-based reset doesn't end other sessions.** `admin.updateUserById` changes the password but existing refresh tokens stay valid until expiry.
- **TRUST-02 Security questions** remain a weaker factor than the email code; the email-code path already exists, so deprecating questions is a product call.
- **UX-01 / TRUST-01** No landing page, privacy policy, terms or support link. Content must reflect real data handling (resumes, Gmail access, portal passwords, AI providers) — needs the owner and ideally legal review; not written here.
- **F-05** Add an explicit `submitted_unverified` state when the confirmation regex doesn't match but no error is visible, instead of today's binary outcome.

## Kept on purpose (differs from the kit)

- **"Apply" still queues a real application** (the product's core feature). The button says what will happen: "Apply with agent" (agent submits on its next run) or "Prepare application" (the agent can't submit on that site, so it prepares answers for you). The kit's "prepare never submits" flow would remove existing behavior, so it was not adopted.
- **No Hybrid filter**: postings only record remote vs not.
- **No `/auth` merge** of sign-in, sign-up and reset: the spec says to wait until email-based recovery replaces security questions.
- **No full status-machine change** (`submission_attempted`, `submitted_verified`…) in the database or agent; only the wording above. That needs agent changes.
- No privacy/terms/help pages (the content has to come from you).
